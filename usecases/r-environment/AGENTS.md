## What this use case is for

Producing reproducible, immutable R environments whose results can be defended
in a regulatory submission. The deliverable is not the environment — it is the
**evidence that the environment reproduces known results**, and the delta report
that shows exactly what changed when it did not.

## Variants

Two independent pinning strategies are maintained in parallel so they can be
compared. Neither is the "real" one.

| Variant | Directory | Strategy |
|---|---|---|
| `renv` | `env/renv/` | `renv.lock` + dated Posit Package Manager snapshot, on a digest-pinned `rocker/r-ver` base |
| `nix` | `env/nix/` | `default.nix` generated by `{rix}`, pinning a dated `rstats-on-nix/nixpkgs` tarball |

Maintaining two costs roughly twice as much CI time, and it is worth it: when
both agree, the result is probably a property of the code; when they disagree,
one of them is wrong and you have found it for free.

## Tolerance discipline

The single rule that matters most here, because getting it wrong is invisible:

**A tolerance is a claim about floating-point arithmetic** — the same
computation, performed in a different order, landing slightly away from where it
did before. It is not a general-purpose "close enough" dial.

- Tolerance applies to **values only**. `length`, `dim`, `names`, `dimnames` and
  `class` are compared exactly on every path. A result that changed shape is a
  different result, not a tolerable deviation.
- The strict path uses `all.equal(tolerance = 0)`. It does **not** use
  `testthat::expect_equal()`, whose default tolerance is ~`1.49e-8` — roughly a
  million times larger than the `1.42e-14` BLAS drift this harness exists to
  detect. A strict path built on it would report an applied tolerance of `0`
  while silently applying `1.49e-8`.
- Environment identity includes platform, architecture, BLAS/LAPACK
  implementation, thread count and CPU kernel. R version and package versions
  alone are not enough: the same digest with different BLAS threading produces
  different numbers.

See [`skills/performance-qualification`](skills/performance-qualification/SKILL.md).
